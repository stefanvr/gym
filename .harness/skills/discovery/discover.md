# Discover

## Define
Investigate one intentional open question before the owner knows whether it should become Goal work or durable Project knowledge. Discovery is a safe, non-authoritative decision space, not Goal-lite or backlog grooming.

## Inputs
Required: an open question or area of uncertainty.

Optional: repository evidence, active Project authority, native docs, Brainstorm material, active methods, installed Extensions, owner preferences, prior Dream proposals.

## Outputs
By default, conversational findings only. A Discovery ends as one of: close with no action; explicitly publish a useful finding through an existing Project owner/documentation surface; or explicitly promote one bounded outcome to Goal.

## Owns
No durable Project or Harness state. Discovery owns only the current transient investigation. It does not own `doc/discovery/` or any backlog artifact.

## Modes
### `explore`
Inspect, reason, compare, question, prototype conceptually, and use fitting methods/Extensions without committing to work.

### `publish`
After explicit owner choice, route a useful finding to the existing owner that may durably record it. Discovery itself does not write Project authority.

### `promote`
After explicit owner choice, hand one bounded actionable outcome to Goal. Candidate outcomes that are not promoted remain non-work.

### `close`
End the investigation without retaining or scheduling anything.

## Method
1. State the question being investigated.
2. Load only evidence useful to that question.
3. Use Brainstorm, methods, Grill, or Extensions only where they increase information value.
4. Keep observations, interpretations, options, and unknowns distinguishable.
5. Do not manufacture a roadmap from possibilities.
6. Ask whether anything is worth publishing or promoting; default to closing transiently.
7. For publication, route to the existing Project authority/documentation owner. For work, route to Goal.

## Completion
Complete when the question is sufficiently understood for the owner to choose close, publish, or promote, or when further investigation has low information value.

## Approval
No lifecycle approval. Publication or promotion requires an explicit owner choice because it crosses from transient thinking into durable Project state or Goal work.

## Invariants
- Discovery is transient and non-authoritative by default
- Discovery may finish with no Goal
- no Discovery backlog is created
- Extensions and methods influence reasoning but never gain authority
- durable Project state is written only through an existing owner
- Goal creation/widening is never implicit
