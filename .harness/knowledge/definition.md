# Knowledge

Reusable technology-conditioned operational knowledge.

Knowledge is cross-project memory.

Nothing here chooses a technology.

Read an entry only when Tech names the technology or the current work directly encounters it.

## Owns

- failure modes
- configuration consequences
- setup traps
- environment distinctions
- proven verification patterns
- examples that remain useful across projects

## Does not own

- technology choices
- project-specific architecture
- project-specific setup state
- general principles that belong in Guides

## Skills

- **Knowledge Lookup** — loads only technology knowledge relevant to current work
- **Knowledge Capture** — records or refines a reusable technology entry from evidenced work
- **Knowledge Check** — checks entries for drift, contradiction, obsolete examples, and misplaced authority

## Entry contract

A technology entry should answer, where useful:

- what happened
- why it was deceptive or costly
- the safe/known pattern
- how to verify it
- the context boundary
- example/configuration snippets that help future use

## Future repository

Knowledge may move to a dedicated knowledge-base repository.

Projects should prefer lookup/reference over copying whole entries into project authority.
