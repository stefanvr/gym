# Shared Mechanisms

These are named reusable behaviors rather than independent skills for now.

They can be extracted when their behavior becomes stable across several skills.

## Brain

Reconciles new information with current understanding.

Typical behavior:

- interpret
- challenge
- reconcile
- expose assumptions
- identify decisions
- distinguish execution correction from requirement change
- reshape the proposed plan

Initially used primarily by Goal.

It may later be shared by:

- specification
- debugging
- review

## Scrutiny

Applies a guide to an object before that object becomes actionable state.

Examples:

- goal scrutiny
- specification scrutiny
- architecture scrutiny

Scrutiny is reasoning, not lifecycle ownership.

## Check

Compares intended state with observed state.

A check prefers evidence over assumption.

It may establish that something is:

- unchanged
- ready
- complete
- blocked
- inconsistent

## Approval

Explicit user acceptance at a meaningful validation boundary.

Approval does not establish factual completion; checking does.

Approval answers:

> Is this accepted sufficiently to continue or land?

Intermediate approval should be exceptional.
