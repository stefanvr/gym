# Project Understand

Performs targeted repository analysis needed to define a Goal or its implementation authority responsibly.

## Define

Inspect only the repository areas needed to remove material uncertainty about the requested outcome, current behavior, relevant native authority, conventions, constraints, and likely change boundary.

## Inputs

Required:

- current request or Goal
- repository state

As needed:

- native documentation and ADRs
- schemas and configuration
- tests and implementation
- UI/application behavior
- design-system and style artifacts
- recent relevant history

## Outputs

Concise evidence-backed findings that can refine the Goal or feed Project Define. Findings remain working material until incorporated into the active Project authority target.

## Owns

No durable Project authority. This skill owns only temporary understanding work.

## Modes

### `goal`

Analyse enough repository context to bound or clarify the Goal.

### `definition`

Analyse a specific subsystem or constraint needed to make Project authority implementation-ready.

## Completion

Complete when the material uncertainty that triggered analysis is resolved, explicitly blocked, or converted into a decision routed to its owner.

## Approval

Reading and analysis require no approval. Any newly proposed Project meaning follows the approval policy of its owning reasoning capability.

## Invariants

- analysis is proportional to the Goal
- current implementation is evidence, not automatic desired-state authority
- native normative artifacts are distinguished from incidental files
- findings do not become Project authority merely by being discovered
- do not analyse unrelated repository areas for completeness theater
